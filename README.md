# دستیار خرید حضوری ترب — نسخه اول

نسخهٔ اول یک پروتوتایپ قابل اجرا و مبتنی بر دیتاست واقعی ترب است. این نسخه روی تجربهٔ فارسی/RTL و موبایل تمرکز دارد و شامل جست‌وجوی محصول، مقایسه، فروشگاه‌های دارای آفر، نزدیک‌یابی، جایگزین‌یابی، برنامهٔ مراجعه، چک‌لیست حضوری و نمایش شفاف وضعیت داده است.

## اجرا

از همین پوشه:

```bash
python server.py
```

سپس مرورگر را روی `http://127.0.0.1:8787` باز کنید.

در اولین اجرا، اگر `torob.db` وجود نداشته باشد، دیتاست موجود در پوشهٔ والد به SQLite تبدیل می‌شود. این مرحله فقط یک‌بار انجام می‌شود.

## محدودیت‌های آگاهانه نسخه اول

- CSV snapshot است؛ موجودی امروز، قیمت نهایی و پاسخ فروشنده از آن استنباط نمی‌شود.
- شماره‌های فروشگاه‌ها به‌هیچ‌وجه نمایش داده یا استفاده نمی‌شوند.
- پیگیری زندهٔ صاحب فروشگاه به اتصال معتبر نیاز دارد؛ این نسخه آن را به‌صورت وضعیت «اتصال واقعی موجود نیست» مدل می‌کند و ادعای تماس نمی‌سازد.
- نقشهٔ بیرونی با مختصات و آدرس داده نمایش داده می‌شود؛ مسیر داخل پاساژ حدس زده نمی‌شود.
- پرداخت و ارسال فقط به‌عنوان اطلاعات ثبت‌شده نمایش داده می‌شوند، نه تضمین.

## نسخه ۱.۲ — چت و مقایسه

### چت با حافظه

- جدول `chat_messages` در همان `torob.db` (ساخته‌شده در `db()`، idempotent).
- `POST /api/chat` حالا `session_id` را می‌پذیرد و آن را برمی‌گرداند؛ تاریخچه از DB خوانده می‌شود نه از کلاینت.
- `GET /api/chat/history?session_id=...` برای بازیابی مکالمه.
- کلاینت `session_id` را در `localStorage` نگه می‌دارد و در بارگذاری صفحه تاریخچه را می‌کشد.
- سازگار با کلاینت قدیمی: اگر تاریخچه‌ای در DB نباشد، همان `messages` ارسالی استفاده می‌شود.

### مقایسهٔ ۲–۳ محصول

- `GET /api/compare?ids=a,b[,c]` — کمتر از ۲ یا بیشتر از ۳ شناسه ⇒ `400`.
- هر ستون: عنوان، برند، دسته، مدل، بازهٔ قیمت ثبت‌شده، ارزان‌ترین فروشگاه، تعداد فروشگاه دارای آفر، نزدیک‌ترین شعبه (اگر موقعیت ثبت شده باشد)، آفر گارانتی‌دار، فروشگاه با ارسال فوری.
- `spec_rows` فقط کلیدهای مشترک بین حداقل دو محصول را می‌آورد (حداکثر ۱۲ ردیف) و همیشه هم‌طول تعداد ستون‌هاست.
- موجودی و پاسخ فروشنده برای هر ستون `unknown` می‌ماند؛ `contacts` هرگز سریالایز نمی‌شود.
- UI: چک‌باکس «مقایسه» روی هر کارت، نوار انتخاب با چیپ‌های قابل حذف، دکمهٔ غیرفعال تا انتخاب دو محصول، و جدول RTL با ستون برچسب چسبان.

### فیلترهای چندگانه

- `GET /api/search` همچنان با قرارداد قبلی کار می‌کند و به‌صورت اختیاری `brand` (تکرارشونده)، `payment` (تکرارشونده)، `warranty=1` و `fast_delivery=1` می‌پذیرد.
- برند روی `products.brand_name` اعمال می‌شود.
- گارانتی، پرداخت و ارسال فوری با `EXISTS` روی آفر/فروشگاه اعمال می‌شوند؛ بنابراین «محصولی که حداقل یک آفر با همهٔ شرایط انتخاب‌شده دارد» برمی‌گردد.
- فیلتر گارانتی فقط وجود شیء گارانتی ثبت‌شده را بررسی می‌کند، نه تأیید کیفیت یا اعتبار آن.
- فیلتر پرداخت فقط وجود `provider_name` ثبت‌شده را بررسی می‌کند؛ کانال تماس یا ضمانت پرداخت نیست.
- فیلتر ارسال فوری فقط مقدار ثبت‌شدهٔ `supports_fast_delivery=true` را نشان می‌دهد؛ وعدهٔ ارسال امروز نیست.
- `/api/meta` فهرست ۸۰ برند پرتکرار و ۳۰ پرداخت‌دهندهٔ ثبت‌شده را برای UI می‌دهد.
- UI فیلترها را در URL به‌شکل واضح ارسال می‌کند و نتیجهٔ فعال‌بودن فیلتر را نشان می‌دهد.
